# Agent2API（KSU 模块）→ iOS 17.0 越狱 IPA 可行性分析与移植方案

结论先行：**这套东西不能"打包"成 IPA**（二进制是 Linux ELF，iOS 内核只认 Mach-O），但**能重编译成 iOS 原生形态**——因为上游网关本体是一个纯 Rust 的独立 crate（`agent2api-server`），除了 Windows 专有分支外没有平台硬绑定。移植后不是"一个 App"，而是 **launchd 守护进程（后端）+ IPA（前端壳）** 的双体结构，与 Android 模块的 `supervisor.sh + WebUI + Agent2Login.apk` 一一对应。

---

## 0. 判定摘要

| 路线 | 形态 | 功能完整度 | 工作量 | 建议 |
|---|---|---|---|---|
| A1 | 守护进程 `agent2api-server`（iOS 原生重编译，launchd 常驻）+ IPA 壳（WKWebView 面板 + 隔离登录容器） | 网关 100%，插件 0%，mihomo 订阅内核 0~30% | 2~3 天 | **主推** |
| A2 | 同上，但网关也编成 staticlib 塞进 App 进程内（离线单机、无需守护） | 同上，且熄屏/挂起即停 | +0.5 天 | 可选叠加（离线模式） |
| B | 纯客户端 IPA：壳只连别的机器上的网关（Android/PC/VPS/Docker） | 100%（后端在别处） | 2 小时 | **立即能用**，先做这个止血 |
| C | 不装 IPA：Safari「添加到主屏幕」PWA（`ui/manifest.webmanifest` + `sw.js` 现成） | 100%（后端在别处） | 0 | 连代码都不用写 |
| D | 越狱机上跑 arm64 Linux VM（UTM/palera1n + QEMU-JIT），VM 内原样跑本模块 + 自带插件二进制 | 100%（含插件、glibc 版、mihomo） | 1 天 + 一台机器的性能代价 | 需要插件时的唯一保真方案 |

**核心结论一句话**：网关能原生跑，插件（`plugins-bin/*` 那两个 ELF）不能；想要插件只能用路线 D 的 Linux 用户态。

## 1. 先跑这几条确认你的机器（决定签名与安装方式）

手机上（NewTerm3 / SSH 均可）：

```sh
uname -a
sw_vers                        # ProductVersion 应为 17.0
id                             # 越狱后应为 uid=0(root) 或可用 sudo
ls -d /var/jb 2>/dev/null      # 有输出 = rootless 越狱（palera1n rootless / Dopamine 系）
which ldid launchctl dpkg
ls /var/jb/Library/LaunchDaemons | head
sysctl -n hw.cputype hw.cpusubtype   # 16777228/2 = arm64e；16777228/0 = arm64
```

判定口径：

- 有 `/var/jb` → 全部路径前缀 `/var/jb`，守护进程放 `/var/jb/Library/LaunchDaemons/`。
- `ldid` 在 → IPA 用 `ldid -S` 签，AppSync Unified / TrollStore 装，无 7 天掉签。
- 没有 `ldid` 但有 `appinst` → 用 `appinst` 装未签名 IPA（同样无掉签）。
- 都没有 → 只能 Sideloadly/AltStore + 开发者证书（7 天重签），守护进程部分改用 `launchctl` 手动 bootstrap。
- `arm64e`（A12 及以上）在 iOS 17.0 上无公开越狱，你既然已越狱，大概率是 A10/A10X/A11 的 iPad 或 iPhone 8/X 类机型（palera1n），或用了 TrollStore 的 arm64e 方案。**这条不影响本方案**，只影响能不能用 `platform-application` 之类私有 entitlement。

## 2. 项目解剖（证据链，全部来自你给的 zip 实测）

### 2.1 二进制指纹

| 文件 | 魔术/类型 | 解释器（PT_INTERP） | 结论 |
|---|---|---|---|
| `bin/agent2api-server` (13.9 MB) | ELF64 LE, `e_machine=0xB7`(AArch64), ET_DYN | `/lib/ld-linux-aarch64.so.1` | **glibc 动态链接**，必须靠模块自带的 `glibc/ld-linux-aarch64.so.1 --library-path glibc/` 拉起 |
| `plugins-bin/agent2api-providers` (9.4 MB) | ELF64 AArch64 | `/system/bin/linker64` | **bionic（NDK r29）**，Android 独立进程 |
| `plugins-bin/agent2api-web-providers` (2.8 MB) | 同上 | `/system/bin/linker64` | 同上 |
| `glibc/*` (3.0 MB) | loader + libc/libm/libgcc_s/libdl/libpthread/librt/NSS | — | 只为跑上面那个 glibc 二进制而存在，**iOS 侧整个目录作废** |
| `apk/Agent2Login.apk` (24 KB, 只有 `classes.dex`) | 系统 WebView 容器 | — | 隔离登录器，iOS 侧用 `WKWebsiteDataStore.nonPersistent()` 等价重写 |

链接依赖实测（`strings` 提取 crate 清单）：`axum 0.8.9 / hyper 1.11 / tokio 1.53 / rustls 0.23 + ring 0.17 / reqwest 0.12 / rusqlite 0.40 + libsqlite3-sys 0.38(bundled) / serde / image / rqrr / bcrypt / aes-gcm / p256 / tokio-tungstenite`。**没有 openssl、没有 keyring、没有 Android JNI、没有 tauri**（`tauri` 只作为字符串残留）。

### 2.2 运行链路（Android）

```
service.sh (late_start, 查 ksud autostart)
  └─ control.sh start
       └─ setsid supervisor.sh
            ├─ dns.sh        → 维护 /data/a2a/resolv.conf 三件套（glibc 没有 netd 才需要）
            ├─ sync-plugins.sh → plugins-bin/* 落到 {plugins}/android-bin/<id>/<版本>/
            ├─ patch-ui.sh   → 重放 ui/m.html 的 A2A_LOGIN_OPEN 注入 + numfmt 补丁 + SW 缓存戳
            └─ glibc/ld-linux-aarch64.so.1 --argv0 agent2api-server --library-path glibc/ bin/agent2api-server
                 └─ 127.0.0.1:3065  HTTP(axum)  ← 面板 ui/ + /api/* + /v1/*
```

要点：`AGENT2API_PROXY_HOME=/data/adb/agent2api`（SQLite + `account.key` + 日志）、`AGENT2API_UI_DIR=<模块>/ui`、`AGENT2API_CAPTCHA_ENABLED=1`、`AGENT2API_SELF_UPDATE=1`；健康检查 `GET /health` → `{"status":"ok"}`；判活走 PID 文件（因为 loader 启动后进程名是 `ld-linux-*`）。

### 2.3 上游源码结构（关键可行性证据）

`github.com/aimod-cc/Agent2API`：

```
desktop-tauri/src-tauri/
├── Cargo.toml           # tauri 桌面壳（workbuddy-proxy-desktop）
└── server/              # ★ 网关本体，独立 crate，零 GUI 依赖
    ├── Cargo.toml       # [lib] agent2api_server + [[bin]] agent2api-server
    └── src/
        ├── lib.rs       # spawn_task（无运行时上下文时落到惰性全局运行时）
        ├── paths.rs     # config_dir(): AGENT2API_PROXY_HOME > WORKBUDDY_PROXY_HOME > $HOME/.agent2api
        ├── bin/agent2api-server.rs   # headless 入口（环境变量解析 + 闸门）
        └── server/
            ├── mod.rs   # ServerState::bootstrap(port, host) / start(&state) -> oneshot::Sender / set_ui_dir
            ├── access.rs, http.rs, static_files.rs, web_shim.rs, altcha.rs
            ├── api/*    # 50+ 路由（accounts/chat/session/checkin/keys/...）
            ├── core/providers/{workbuddy,zcode,qoder,catpaw,autoclaw,codearts,trae,cline,kuku,loomy,orcaterm,officeace,raccoon,antigravity,accio,monkeycode,commandcode,custom,...}
            ├── core/sub_kernel/*   # mihomo sidecar（下载+spawn 独立二进制，GPL 聚合）
            └── db/*     # SQLite（bundled）
```

`server/Cargo.toml` 里的平台专有依赖只有一段 `[target.'cfg(windows)'.dependencies] windows 0.61`，**没有任何 `cfg(target_os="linux"/"android")` 的硬依赖**。`reqwest` 开了 `system-proxy`（Apple 平台走 `SystemConfiguration`），`tokio` 开了 `process`（只给 Qoder 国际版签到拉 `runtime-info` 子进程用）。这就是"能移植"的全部底气。

### 2.4 面板 UI 侧

- `ui/m.html` + `ui/m/mobile.js` + `ui/m/mobile.css`：移动端 PWA，已含 `sw.js`（`const CACHE = 'agent2api-mobile-fa0e44f4e707'`）与 `manifest.webmanifest`。
- zip 里的 UI **已经打好登录器补丁**：`m.html` 里有 1 处 `A2A_LOGIN_OPEN` 定义块（含 `stateCapture` fetch 拦截、`window.ksu.exec(... am start ... agent2api://login ...)` 三重拉起），`mobile.js` 里有 2 处调用点。iOS 侧**不需要改这些文件**，只要接管 `window.A2A_LOGIN_OPEN` 或拦截 `window.open` 新建窗口即可。
- 语言：zh-Hans / zh-Hant / en / ja / ko / pt-BR（`ui/i18n/*`），`ui/islands/ui.js` 是 2.2 MB 的面板 bundle。

## 3. 逐组件移植可行性矩阵

| # | 组件 | 能否移植 | 判定依据 | iOS 对应物 |
|---|---|---|---|---|
| 1 | 网关 HTTP 服务（axum，127.0.0.1:3065） | ✅ 100% | 纯 Rust + `std::net::TcpListener::bind`（`server/mod.rs:954`），loopback 在 iOS 应用/守护进程里均可 bind，无需 entitlement | 原样 |
| 2 | 23 个提供商适配器 | ✅ 100% | 全在 `core/providers/*`，纯 HTTP + 加解密（ring/AES/RSA/P-256） | 原样 |
| 3 | TLS 出网（rustls + webpki-roots） | ✅ 100% | 纯 Rust，不依赖系统 OpenSSL；iOS 反而更省事 | 原样 |
| 4 | SQLite（bundled amalgamation） | ✅ 100% | 编译期把 `sqlite3.c` 静态链进来，用 Xcode SDK 的 clang 编即可 | 原样 |
| 5 | 数据目录/配置 | ✅ 需改一处 | `paths.rs` 认 `AGENT2API_PROXY_HOME` | 守护进程用 `/var/mobile/Library/agent2api`，App 内嵌模式用容器 `Library/Application Support/agent2api` |
| 6 | 面板 UI（`ui/`） | ✅ 100% | 静态资源 + `/api/*` 同源，`static_files.rs` + `web_shim.rs` 现成 | `--target aarch64-apple-ios` 守护进程直接托管；App 里 `WKWebView` 加载 `http://127.0.0.1:3065/` |
| 7 | WebUI 壳 / KernelSU 桥（`webroot/`、`ksu.exec`） | ❌ 作废 | iOS 没有 KernelSU | WKWebView 即壳；需要提权时用 `posix_spawn` root helper 或越狱 Ruby/`su` 管道 |
| 8 | `supervisor.sh`（崩溃自恢复 + 退避） | ✅ 等价 | launchd 的 `KeepAlive{SuccessfulExit=false}` + `ThrottleInterval` | LaunchDaemon plist |
| 9 | `service.sh` / `boot-completed.sh`（开机自启） | ✅ 等价 | launchd `RunAtLoad` | LaunchDaemon plist |
| 10 | `control.sh`（start/stop/restart/status/rollback） | ✅ 等价 | — | `launchctl kickstart/bootout` + 两个 `.xpc` 二进制版本并存 |
| 11 | `ksud module config`（port/host/autostart） | ✅ 等价 | — | plist 的 `EnvironmentVariables` + 一个小 `config.json` |
| 12 | `dns.sh`（resolv.conf 三件套 + GDNS） | ❌ 作废 | iOS 走 `mDNSResponder`，libSystem 无 `/etc/resolv.conf` 依赖 | 删除；VPN 场景由系统解析器自动跟随 |
| 13 | `glibc/` 运行时 + `ld-linux` 用法 | ❌ 作废 | iOS 内核不加载 ELF，也没有 `ld.so` | 直接编 Mach-O |
| 14 | `sepolicy.rule` | ❌ 作废 | SELinux 不存在 | 越狱下无沙盒限制（`com.apple.private.security.no-sandbox`） |
| 15 | 隔离登录器（`Agent2Login.apk`） | ✅ 100% | 本质是"一次性 cookie 罐 + 回调闭环" | `WKWebView` + `WKWebsiteDataStore.nonPersistent()` + `createWebViewWith` 拦截 |
| 16 | `patch-ui.sh`（sed 打补丁） | ✅ 可免 | 因为 zip 里的 UI 已打好补丁 | `WKUserScript`（`.atDocumentStart`）+ `Object.defineProperty` 锁死 `A2A_LOGIN_OPEN`，或直接靠"新窗口拦截"完全不碰 JS |
| 17 | 面板自更新（`AGENT2API_SELF_UPDATE=1`） | ⚠️ 必须关 | 会下载 glibc ELF 覆盖自身，iOS 上直接砖 | 设 `0`，升级走"重编译 + `launchctl kickstart -k`" |
| 18 | 插件系统（`plugins-bin/*`，第三方 provider） | ❌ 0% | 网关用 `exec` 拉起 **Android/GNU ELF** 子进程，iOS 不能 `exec` 非 Mach-O、且 App 沙盒禁止 `fork/exec` | 需插件作者出 `aarch64-apple-ios` 构建；否则删插件目录，只用内置 23 家 |
| 19 | mihomo 订阅内核（`core/sub_kernel`，sidecar） | ⚠️ 0~30% | 下载 + `Command::new` 起独立二进制；mihomo 有 `darwin-arm64` 官方产物 | 越狱守护进程里"未签名 darwin 二进制 + posix_spawn"理论可跑，需实测；失败就把订阅节点功能置灰 |
| 20 | Qoder 国际版签到的 `runtime-info` 子进程 | ⚠️ 降级 | `providers/qoder/risk.rs` 解 npm tgz 里的 ELF 再 spawn | 该家签到走"需重登"，其余功能正常 |
| 21 | `AGENT2API_SELF_UPDATE` 的 `/api/update/restart` | ❌ | 靠进程退出 + 容器拉起 | 守护进程形态下改成 `launchctl kickstart -k gui/...`，或直接不用 |

综合：**网关本体 + 全部内置提供商 + 面板 + 登录容器 ≈ 100% 可移植；插件 + Linux sidecar ≈ 不可移植**。这就是"能做成 IPA，但要接受两个功能缺口"的准确含义。

## 4. 目标架构（形态 A1，主推）

```
iOS（越狱，rootless：/var/jb）
├── LaunchDaemon  com.chiyu.agent2api
│     /var/jb/usr/local/bin/agent2api-server        ← cargo build --target aarch64-apple-ios（Mach-O）
│     env: AGENT2API_PROXY_HOME=/var/mobile/Library/agent2api
│          AGENT2API_UI_DIR=/var/jb/usr/local/share/agent2api/ui
│          AGENT2API_HOST=127.0.0.1  PORT=3065  CAPTCHA_ENABLED=1  SELF_UPDATE=0
│     RunAtLoad + KeepAlive{SuccessfulExit=false} + ThrottleInterval=5  ← 取代 service.sh/supervisor.sh
│     StandardOut/Err → /var/mobile/Library/agent2api/server.log
│     UserName=mobile                        ← 让 App 与守护进程共用同一批文件权限
│
└── App  /Applications/Agent2API.app（ldid 签名，AppSync/TrollStore 安装）
      ├── WKWebView → http://127.0.0.1:3065/m            ← 取代 WebUI + ui/
      ├── 状态条：健康探测 / 启停（launchctl 经 root helper）
      └── 隔离登录容器：WKWebsiteDataStore.nonPersistent()  ← 取代 Agent2Login.apk
```

选 `UserName=mobile` 而不是 root 的理由：面板写 SQLite/WAL、`account.key`、日志都落在 `/var/mobile/Library/agent2api`，App（mobile 身份）和守护进程同 uid，不会出现"App 读不到 root 写的库"。3065 > 1024，无需提权绑定。

## 5. 路线 A1 落地步骤

### Step 1 · 工具链（macOS，Apple Silicon 推荐）

```bash
xcode-select -p                     # 需要 Xcode 15+（iOS 17 SDK）
rustup update
rustup target add aarch64-apple-ios aarch64-apple-darwin
cargo install cargo-lipo ldid 2>/dev/null || true
brew install ldid dpkg ldid-procursus 2>/dev/null || true
```

Rust 1.88+ 必须（`rusqlite 0.40 → libsqlite3-sys 0.38` 的 MSRV）。

### Step 2 · 取源码 + 打 iOS 补丁

```bash
git clone https://github.com/aimod-cc/Agent2API.git
cd Agent2API/desktop-tauri/src-tauri
```

打三处补丁（`patches/0001-ios.patch` 的逻辑，逐条）：

1. **`server/Cargo.toml`**：把 `reqwest` 的 `system-proxy` 特性按目标关掉（`system-configuration` 在 iOS SDK 上大概率编不过，且 App/守护进程场景不需要"跟随系统代理"）：

```toml
[target.'cfg(not(target_os = "ios"))'.dependencies]
reqwest = { version = "0.12", default-features = false, features = ["json", "stream", "rustls-tls", "socks", "system-proxy"] }

[target.'cfg(target_os = "ios")'.dependencies]
reqwest = { version = "0.12", default-features = false, features = ["json", "stream", "rustls-tls", "socks"] }
```

2. **`server/src/server/core/sub_kernel/runtime.rs` 与 `providers/qoder/risk.rs`**：给 `Command::new / std::process::Command` 外面套 `#[cfg(not(target_os = "ios"))]`，iOS 分支直接 `Err("该功能在 iOS 上不可用")`。这样编得过，且面板上点"下载内核/国际版签到"只报错不崩。

3. **`server/src/lib.rs`**：`panic = "abort"`（release profile 已有）+ 追加一个 iOS 用的 C ABI 模块（见 Step 5，或独立 crate 免改上游）。

> 不想改上游代码也可以：本方案已给出**独立 crate `agent2api-ios`**（`ios-ffi/`），只 `path` 依赖上游 `server/`，用 `[patch]`/环境变量控制特性，把补丁面积压到最小。

### Step 3 · 编译守护进程（Mach-O，launchd 可拉）

```bash
cd Agent2API/desktop-tauri/src-tauri
export IPHONEOS_DEPLOYMENT_TARGET=15.0
cargo build -p agent2api-server --release --target aarch64-apple-ios
file target/aarch64-apple-ios/release/agent2api-server
# → Mach-O 64-bit executable arm64
```

要点：

- `--target aarch64-apple-ios` 生成的是 **iOS 平台的 Mach-O 可执行体**，`LC_BUILD_VERSION` 平台=iOS，dyld 认；不要用 `aarch64-apple-darwin`（平台=macOS，dyld 直接拒）。
- 链接时会去找 iOS SDK 的 `libSystem.tbd`，`ring` 的 aarch64 汇编、`libsqlite3-sys` 的 C 源码都由 SDK clang 编，Xcode 15 下都能过。
- strip（release profile 已 `strip=true, lto=true, panic=abort`）。

签名（越狱必需，否则 AMFI 杀）：

```bash
ldid -S target/aarch64-apple-ios/release/agent2api-server
codesign -dv --entitlements :- target/aarch64-apple-ios/release/agent2api-server 2>&1 | head
```

守护进程**不需要** entitlement（越狱 launchd 拉起的无沙盒进程）；若你的越狱环境给进程挂了 sandbox profile，则加：

```xml
<key>com.apple.private.security.no-sandbox</key><true/>
<key>platform-application</key><true/>     <!-- 仅 CoreTrust/TrollStore 环境可用 -->
```

### Step 4 · 装守护进程

```bash
DEV=  # 手机 IP 或 usbmuxd: ssh root@<ip>
scp agent2api-server root@$DEV:/var/jb/usr/local/bin/
scp -r ui root@$DEV:/var/jb/usr/local/share/agent2api/
scp daemon/com.chiyu.agent2api.plist root@$DEV:/var/jb/Library/LaunchDaemons/
ssh root@$DEV '
  mkdir -p /var/mobile/Library/agent2api && chown mobile:mobile /var/mobile/Library/agent2api
  chmod 755 /var/jb/usr/local/bin/agent2api-server
  ldid -S /var/jb/usr/local/bin/agent2api-server
  chown root:wheel /var/jb/Library/LaunchDaemons/com.chiyu.agent2api.plist
  chmod 644 /var/jb/Library/LaunchDaemons/com.chiyu.agent2api.plist
  launchctl bootstrap system /var/jb/Library/LaunchDaemons/com.chiyu.agent2api.plist 2>/dev/null \
    || launchctl load -w /var/jb/Library/LaunchDaemons/com.chiyu.agent2api.plist
  sleep 3; curl -s http://127.0.0.1:3065/health; echo
'
```

plist 内容见 `daemon/com.chiyu.agent2api.plist`（本仓库已给）。

`/var/jb/Library/LaunchDaemons` 在 rootless 下由 `jbinit` 在用户态 launchd 的 `LaunchDaemons` 搜索路径里，`bootstrap system` 通常可用；不行就用 `launchctl load -w`（legacy）。重启用：

```bash
launchctl kickstart -k system/com.chiyu.agent2api
```

### Step 5 · （可选，形态 A2）把网关编成 staticlib 塞进 App

用于"完全离线、不要守护进程"的场景。`ios-ffi/` 已给完整 crate：把 `ServerState::bootstrap → access::* → set_ui_dir → start` 这条 headless 时序原样搬进 C ABI，Swift 侧 `a2a_start(home, ui, port)` 即可。

```bash
cd agent2api-ios/ios-ffi
cargo build --release --target aarch64-apple-ios
# → target/aarch64-apple-ios/release/libagent2api_ios.a
```

注意：`ui/` 此时要作为 App bundle resource 打进 IPA（`AGENT2API_UI_DIR` 指向 `Bundle.main.resourceURL/ui`），`AGENT2API_PROXY_HOME` 指向 `Library/Application Support/agent2api`。App 被挂起时网关随之冻结——所以 A2 只在"前台用一下"时成立，常驻仍要走 A1。

### Step 6 · 造 IPA（Swift 壳）

工程文件结构（见 `app/Agent2API/`）：

```
AppDelegate.swift        窗口 + 根控制器
PanelViewController.swift  WKWebView 加载 127.0.0.1:3065/m + 健康探测 + 重试 + 底部状态条
LoginContainer.swift      隔离登录容器（nonPersistent dataStore + 自定义 scheme 回调 + 登完即焚）
Bridge.swift              window.A2A_LOGIN_OPEN 注入 + createWebViewWith 拦截
Info.plist                ATS 例外（127.0.0.1/localhost 明文）、UIFileSharingEnabled 关、背景模式无
Agent2API-Bridging-Header.h  a2a_start/a2a_stop（仅 A2 需要）
entitlements.plist
```

三个关键实现点：

1. **ATS**：iOS 默认禁明文 HTTP。必须给 `127.0.0.1` / `localhost` 开例外，否则 WKWebView 白屏：

```xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsLocalNetworking</key><true/>
  <key>NSExceptionDomains</key>
  <dict>
    <key>127.0.0.1</key><dict>
      <key>NSExceptionAllowsInsecureHTTPLoads</key><true/>
      <key>NSIncludesSubdomains</key><true/>
    </dict>
    <key>localhost</key><dict>
      <key>NSExceptionAllowsInsecureHTTPLoads</key><true/>
    </dict>
  </dict>
</dict>
```

2. **登录器接管**（对应 `patch-ui.sh`）：两条路，任选或都上——
   - 原生侧：`WKUIDelegate.createWebViewWith(_:configuration:)`。`mobile.js` 在非 Android UA 下走 `window.open($.url,'_blank')`，WKWebView 会把 `target=_blank` 交给这个方法，我们在这里用 `nonPersistent()` 的配置建一个隔离容器。**完全不用改 JS、不用改 ui/**。
   - JS 侧：`WKUserScript` 在 `.atDocumentStart` 用 `Object.defineProperty` 把 `window.A2A_LOGIN_OPEN` 锁成 getter（页面后续 `window.A2A_LOGIN_OPEN = fn` 静默失败），getter 返回调用 `WKScriptMessageHandler` 的实现。这样连"手机端登录方式回落"都不需要。

3. **回调闭环**：登录成功后的 loopback 重定向（`http://127.0.0.1:3065/api/session/login/callback?...`）在隔离容器里直接命中本机网关，Session 落库；自定义 scheme（`office-raccoon://`、`autoclaw://` 等）由 `decidePolicyFor` 截获，转成 `POST /api/session/login/callback`。收尾统一 `WKWebsiteDataStore.removeData(ofTypes:modifiedSince:)` + `URLCache.shared.removeAllCachedResponses()`，与 Android 版"焚毁 cookie/localStorage/缓存/表单/历史"对齐。

打包脚本（无证书，`CODE_SIGNING_ALLOWED=NO` + `ldid`）：

```bash
cd agent2api-ios
./scripts/build-ipa.sh          # 产出 build/Agent2API.ipa
```

脚本内部：`xcodebuild -sdk iphoneos -arch arm64 CODE_SIGNING_ALLOWED=NO` → 组装 `Payload/Agent2API.app` → `ldid -Sapp/entitlements.plist` → `zip -ry`。

## 6. 路线 B：纯客户端 IPA（今天就能装上）

不带网关，只当面板客户端。用途：网关继续跑在 Android 手机/PC/VPS 上（它本来就是 `AGENT2API_HOST=0.0.0.0` 的 headless 形态），iOS 只负责好看的壳 + 局域网/内网访问。

```swift
// 40 行版本：把 baseURL 换成 http://<网关LAN IP>:3065/m
final class PanelViewController: UIViewController {
    private let web = WKWebView()
    override func loadView() {
        let cfg = WKWebViewConfiguration()
        cfg.defaultWebpagePreferences.allowsContentJavaScript = true
        view = WKWebView(frame: .zero, configuration: cfg)   // 换成 web
    }
    override func viewDidLoad() {
        super.viewDidLoad()
        guard let url = URL(string: "http://192.168.1.50:3065/m") else { return }
        (view as! WKWebView).load(URLRequest(url: url))
    }
}
```

这套只要 `Info.plist` 里对目标域名开 ATS 例外（或 `NSAllowsArbitraryLoads=true`，自用可接受）。签名同 Step 6。

**更快的一步**：`ui/manifest.webmanifest` + `sw.js` 都在，Safari 打开 `http://<网关IP>:3065/m` → 分享 → 添加到主屏幕，零代码得到全屏 PWA。先这么用，等 A1 编好再换。

## 7. 路线 D：要"插件也不丢"的唯一方案（Linux 用户态）

`plugins-bin/*` 是 Android bionic ELF，`sync-plugins.sh` 里的 GNU 插件还要 `ld-linux` 兼容层——iOS 内核永远不给你 ELF loader。保真只有一条：**在 iOS 上跑一个 arm64 Linux 用户态**。

1. 越狱机装 UTM（App Store 版无 JIT 很慢；越狱后可注入 `dynamic-codesigning` entitlement 打开 JIT，`palera1n` 环境用 `UTM SE` + JIT 补丁）。
2. 起一台 `arm64` Linux（Debian/Ubuntu cloud image，512 MB~1 GB 内存足够）。
3. VM 内**原样**执行本模块的逻辑：`apt install libc6` → 解压模块 → `glibc/ld-linux-aarch64.so.1 --library-path glibc bin/agent2api-server`，`plugins-bin/*` 放 `{plugins}/android-bin/<id>/<版本>/` 照旧（bionic 二进制在 glibc 系统上跑不了，改放 GNU 版插件——也就是模块 `plugin-fix.sh` 想解决的那类），`dns.sh` 照旧有效（Linux 有 `/etc/resolv.conf`）。
4. iOS 上装路线 B 的壳，`baseURL` 指到 VM 的 `127.0.0.1`（UTM 端口转发 3065）。

代价：VM 常驻吃电、面板响应略慢、启动要等 VM。**只在确实需要那两家插件 provider 时才值得**。

## 8. 风险清单与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| `system-configuration`（reqwest system-proxy）在 iOS SDK 编不过 | 高 | 编译中断 | Step 2 补丁 1，按 target 关特性 |
| `ring` aarch64-apple-ios 汇编报错（旧工具链） | 中 | 编译中断 | 用 Xcode 15+ 的 clang；`ring` 0.17.14 已支持 iOS |
| `chrono` 本地时区在 iOS 返回 UTC | 中 | 签到/统计时刻偏 8 小时 | 面板里把时区设成 `Asia/Shanghai`；或给 `iana-time-zone` 打 iOS 分支返回固定偏移 |
| Rust iOS target 的可执行体被 AMFI 拒 | 中 | 守护进程起不来 | `ldid -S` 重签；`launchctl` 日志 `/var/log/com.apple.xpc.launchd/*` 看 `OS_REASON_CODESIGNING` |
| App 与守护进程文件权限打架 | 中 | 面板报 SQLITE_CANTOPEN / 只读 | plist 里 `UserName=mobile`，目录 `chown mobile:mobile`（Step 4 已含） |
| 面板 SW 缓存住旧构建 | 低 | 白屏/错版 | 换 `ui/` 时同步改 `sw.js` 的 `CACHE` 串（`patch-ui.sh` 的 md5 戳逻辑可抄成一个 `make ui` 步骤） |
| `AGENT2API_SELF_UPDATE` 被误开 | 低但致命 | 下载 ELF 覆盖自身 → 网关永久起不来 | plist 里硬写 `0`；面板"软件更新"按钮不接线 |
| 插件 provider 在面板里仍显示 | 高 | 用户点了报错 | 删 `/var/mobile/Library/agent2api/plugins/` 并在 UI 里隐藏插件页（`mobile.js` 侧 `plugin_category` 分支） |
