# Agent2API 手机面板 UI 功能差距分析

> 分析对象：`Agent2API 3.4.182`
> 目标：评估如果后期**移除桌面面板 `/`，只保留手机面板 `/m`**，还缺哪些功能。
> 结论先行：手机面板已经覆盖大部分核心页面，但**目前还不能安全移除桌面面板**。主要缺口集中在账号编辑、网关 Key 管理、插件设置、安全/备份/系统设置、路由和工具管理。
>
> 第二轮补充审计后，P0 从 5 项扩展到 7 项：新增 **iOS 面板登录持久化** 和 **整库备份/恢复**；另外补充了插件自定义 UI、文件下载/分享、多服务器、supervisor 生命周期等遗漏。
>
> 第四轮已完成源码复核：上游 `aimod-cc/Agent2API` 的 `v3.4.2` 手机源码已拉取并推送到本仓库，commit `cedab6c`；`pnpm exec tsc --noEmit` 和 `pnpm run build` 均通过，构建出的 `mobile.js` 与当前 `3.4.182` 的 bundle SHA-256 完全一致。本文中与源码冲突的旧结论已用“源码复核”修正。

## 1. 分析方法

本次检查了：

- 手机面板 bundle：`ui/m/mobile.js`、`ui/m/mobile.css`、`ui/m.html`
- 桌面面板 bundle：`ui/islands/ui.js`、`ui/app.js`、`ui/sidebar-layout.js`
- iOS 原生壳：`agent2api-ios/app/Agent2API/PanelViewController.swift`
- 插件与网关 API 调用点
- 手机/桌面 UI 的中文字符串、页面路由、API 路径

说明：

- 手机 bundle 是压缩后的单文件，部分功能只能通过路由、字符串、API 调用判断；“可能缺失”会在表中标注。
- “桌面面板有”不等于“手机面板一定没有”；本报告只把**有明确代码/文案/接口证据**的列为确认缺口。

## 3. 确认的功能缺口（按严重级别）

### P0：移除桌面前必须补齐

#### 3.1 网关 Key 管理

**现状：**

- 手机 `keys` 页面可以：查看、复制明文、启用/禁用、删除已有 Key；
- 手机没有：新建 Key、编辑可用范围（提供商/模型白名单）、轮换等完整管理能力；
- 桌面面板才有完整的 Key 创建和范围编辑。

**证据：**

- 手机源码 `KeysPage.tsx` 只调用 `fetchKeys`、`setKeyEnabled`、`deleteKey`，没有创建/范围更新调用；
- 源码注释写明：“可用范围用一行摘要，完整编辑器在桌面端：白名单是多选，窄屏上做多选既费事又容易点错。”

> 之前把手机 Key 页说成“完全只读”不准确：它已经支持复制、启停、删除；真正缺的是**新建和范围编辑**。

**影响：**

移除桌面后，用户无法在手机上创建第一把 Key，也无法调整 Key 的模型/提供商权限。

**建议：**

- 手机 Key 页增加：新建、编辑、删除、启用/停用、复制、可用范围选择；
- 复用桌面 API；
- 首次安装引导必须能在手机端完成 Key 创建。

---

#### 3.2 账号凭证编辑与导入

**现状：**

手机端可以管理已有账号、签到、插件；新增账号要求 provider 声明“动态登录方式”。  
手机 bundle 中明确提示：

```text
手机端可管理已有账号、签到、插件；新增账号请使用提供商自带的动态登录入口，
桌面端用于编辑凭证和改写客户端配置。
```

**缺口：**

- 手工填写/修改 API Key、Cookie、Refresh Token、JWT 等凭证；
- 导入凭证文件（JSON/CSV/客户端配置）；
- 编辑已有账号的凭证字段；
- 查看/复制完整凭证；
- 把网关 Key/Base URL 写回客户端配置；
- 批量编辑账号、批量导入、批量导出。

**影响：**

- 很多 provider 没有声明动态登录，手机端无法新增；
- 已有账号凭证过期后，手机端无法直接修复，必须切桌面；
- 小浣熊（raccoon）就是实际案例：手机端提示“此提供商未声明动态登录方式，请使用桌面面板”。

**建议：**

- 手机账号编辑页增加“凭证编辑”模式；
- provider 登录 schema 同时渲染桌面和手机表单；
- 支持从文件导入/导出；
- 对没有移动登录声明的 provider，至少提供“手动填写凭证”兜底。

---

#### 3.3 插件 GitHub 令牌

**现状：**

- 手机已经有 `GithubAccessSettingsPanel`：在「插件设置」底部可以配置 GitHub 访问方式、官方源、加速源/镜像；
- 但手机没有 `GitHub 令牌` 字段；
- 手机插件页只显示“GitHub 接口限流中，请在插件设置的 GitHub 令牌中填写凭证”，用户找不到填 token 的地方。

**影响：**

- 手机端可以改镜像/加速源，但不能填 token；
- 无 token 时仍然受 GitHub API 60 次/小时限制；
- 只能切桌面或手动安装 zip；
- 用户自己的仓库也不能绕过 GitHub API 限流。

**建议：**

- 在手机「插件设置 → GitHub 访问」里增加 GitHub Token 输入、保存、清除、状态显示；
- 设置保存到网关服务端，桌面/手机共用；
- 明确提示需要 `public_repo` / Contents / Releases 只读权限；
- 不要把“GitHub 访问/镜像”误认为“GitHub 令牌”；两者是不同配置。

> 更正：手机不是完全没有 GitHub 设置；它已有镜像/加速源配置，缺的是 token 字段。

---

#### 3.4 插件设置与更新策略

**现状：**

手机插件页有安装、卸载、更新、从文件安装等入口；但桌面插件设置更完整。

**确认/可能缺口：**

- GitHub Token（确认缺失；手机已有 GitHub 访问方式/镜像设置，但没有 token 字段）；
- 插件下载源/镜像、加速下载源管理；
- 官方签名/未签名策略；
- 自动更新、自动安装官方包、beta 通道的完整设置（手机有部分 beta/通道字段，但入口和桌面不完全一致）；
- 插件安装失败日志、健康检查、重新加载；
- 插件版本/签名/来源/兼容性详情。

**影响：**

手机端遇到限流、签名失败、镜像失败时，无法自行恢复。

**建议：**

- 把桌面插件设置页完整搬到手机；
- 至少提供：Token、更新通道、自动更新、镜像源、签名策略、安装日志。

---

#### 3.5 安全与面板认证设置

**现状：**

手机端有登录/退出，但没有完整的安全设置页。

**桌面有、手机未确认有：**

- 修改面板管理员密码；
- 面板登录方式/会话策略；
- 是否允许未配置 Key 访问；
- API Key 认证开关；
- 面板访问来源/监听地址；
- CORS/开发者模式；
- 验证码/PoW 开关；
- 登录会话/刷新令牌管理。

**影响：**

移除桌面后，用户无法在手机上修改管理员密码或调整安全策略。

**建议：**

手机设置页增加“安全”分组，至少包含修改密码、认证开关、会话退出。

---

### P1：影响完整度，但不一定阻塞首次使用

#### 3.6 路由配置

**现状：**

- 桌面有独立 `routing` 页面；
- 手机没有 `routing` 路由；
- 手机 `models` 页只覆盖模型列表、映射、队列、启停等子集。

**可能缺失：**

- 路由组/路由配置；
- 提供商/账号顺序与回退；
- 路由参与成员、失败后备选；
- 路由规则、模型别名、分组；
- 路由预演/调试视图；
- 旧版全局参与设置迁移。

**影响：**

手机只能做简单模型映射，无法完成完整路由编排。

**建议：**

在手机 `models` 页增加“路由”二级页，或新增独立 `routing` 路由，复用桌面配置 API。

---

#### 3.7 工具服务 / MCP / Skill

**现状（源码复核）：**

手机有 `tools` 和 `servers` 页面：

- `ToolsPage` 管的是网关侧「网络搜索」和「视觉分析」服务；
- `AgentPage` 可以查看/管理已接入 AI 客户端的模型配置、提示词、Skill、MCP，源码注释写明“所有操作都在网关侧”；
- 手机端不做“本机客户端安装”：`ToolsPage` 注释明确说 Skill/MCP 写客户端目录的安装在桌面端完成。

**桌面独有接口：**

```text
/api/tools/api-keys
/api/tools/install-mcp
/api/tools/install-skill
/api/tools/uninstall-mcp
/api/tools/uninstall-skill
```

**缺口：**

- 把 Skill/MCP 安装/卸载到**本机客户端目录**；
- 工具 API Key 的本地安装/写入；
- 工具服务文档/接入信息的桌面式管理；
- 手机没有本地文件系统，无法执行 stdio MCP / 本地 Skill 进程。

**影响：**

不是“手机完全看不到 MCP/Skill”：Agent 页可以管理网关侧资源。  
真正缺的是桌面式“安装到本机客户端”和本地进程。

**建议：**

- 保留 AgentPage 作为 MCP/Skill 的远程管理入口；
- 把“本机安装/写入客户端目录”明确标为桌面专属；
- 如需要，增加“远程 MCP 服务”配置，而不是硬搬本地 stdio。

---

#### 3.8 自定义提供商

**桌面独有接口：**

```text
/api/custom-providers/fetch-models
/api/custom-providers/update
/api/custom-providers/remove
```

**缺口：**

- 新建/编辑自定义提供商；
- 拉取模型列表；
- 修改 Base URL、协议、模型映射；
- 删除自定义提供商；
- 自定义提供商与 Key 的授权范围联动。

手机 bundle 只有少量“自定义提供商”字符串，未发现完整编辑页。

---

#### 3.9 备份 / 恢复 / 数据迁移

**现状：**

手机设置页没有完整备份/恢复入口。

**桌面有：**

- 数据备份/恢复；
- 配置导入/导出；
- 数据库/配置迁移；
- 重置数据；
- 安装信息/系统信息；
- 日志导出。

**影响：**

手机端无法备份账号/Key/配置，也无法在换机/重置前导出。

**建议：**

手机设置页增加“数据”分组：备份、恢复、导出日志、重置数据。

---

#### 3.10 系统/服务控制（已修正）

**手机其实已经有：**

- `SystemInfoSheet`：本机应用版本、界面版本、运行形态、操作系统、监听地址、已运行时间、数据目录、日志文件、账号/模型/Key 数量、安全摘要、复制全部信息；
- `AppUpdatePanel`：PWA/应用更新；
- `SettingsPage`：网关状态、API 地址、客户端识别、Key 复制、退出登录。

**仍然缺：**

- supervisor 状态/重启/停止；
- 网关服务重启（不是 App 更新）；
- 安装包形态/安装目标（iOS deb 场景意义有限）；
- 完整备份/恢复；
- 修改密码/安全设置。

**影响：**

排障信息大部分已有；缺的是“服务控制”和“安全/备份”，不是所有系统信息。

**建议：**

手机设置增加“服务”分组：supervisor 状态、重启 supervisor、停止/启动网关、复制诊断信息。  
`SystemInfoSheet` 继续保留，不要重复造。

#### 3.11 日志/报表高级能力

手机有请求日志、运行日志、报表，但桌面通常还有：

- 列显示/隐藏/排序；
- 高级筛选组合；
- 日志导出；
- 报表维度/时间范围/分页细节；
- 批量复制/批量操作；
- 请求详情中的完整上下文/重试链路。

手机是卡片式 UI，部分表格能力天然弱化。  
建议至少补：导出、时间范围、关键筛选、请求详情。

### P2：体验/一致性缺口

#### 3.12 表格与批量操作

桌面大量使用表格：

- 账号表；
- Key 表；
- 请求日志表；
- 插件表；
- 工具表。

手机使用卡片/列表，缺少：

- 列设置；
- 多选批量操作；
- 排序；
- 表头固定；
- 宽表格横向滚动；
- 批量启用/停用/删除。

不影响核心功能，但影响重度管理。

#### 3.13 桌面面板专有交互

- 桌面面板的拖拽排序；
- 多栏布局；
- 右键菜单；
- 文件选择器；
- 大屏预览/对比；
- iframe/文档双栏。

手机端需要逐页确认是否有等价交互，不能直接假设卡片布局能覆盖。

#### 3.14 登录容器与 provider 文档

手机原生壳已有隔离登录容器，但：

- 部分 provider 的登录方式只在桌面 provider 文档/表单里声明；
- 手机端只渲染“动态登录方法”；
- provider 自定义页面（如小浣熊客户端登录态文件）可能仍依赖桌面入口。

这部分需要 provider 级别适配，不能只改一个通用设置页。

## 5. 如果确定要移除桌面面板：建议顺序

### 阶段 1：P0（必须）

1. 手机 Key 管理（新建/编辑/删除/范围）
2. 手机账号凭证编辑 + 导入/导出
3. 手机 GitHub Token
4. 手机插件设置/更新策略
5. 手机安全设置（改密码/认证/会话）

完成这 5 项后，普通用户可以在手机上完成“安装 → 登录 → 建 Key → 加账号 → 装插件 → 日常使用”的闭环。

### 阶段 2：P1（完整度）

6. 路由配置页
7. MCP/Skill/工具 API Key
8. 自定义提供商
9. 备份/恢复/日志导出
10. 系统/更新信息

### 阶段 3：P2（体验）

11. 表格列设置/批量操作/排序
12. 请求详情/报表高级筛选
13. provider 级移动登录适配
14. 移除原生“桌面面板”按钮和 `/` 入口

最后一步再移除桌面 UI，否则会遇到大量“这个功能只能切桌面”的回退。

## 6. 证据附录

### 6.1 手机端明确的限制文案

```text
手机端可管理已有账号、签到、插件；新增账号请使用提供商自带的动态登录入口，
桌面端用于编辑凭证和改写客户端配置。
```

```text
此提供商未声明动态登录方式，请在网关桌面面板使用其既有入口；
手机端不会猜测凭证字段。
```

### 6.2 原生壳的 Key 页说明

`PanelViewController.swift` 中曾写明：

```text
手机面板的「网关 Key」页是只读的（上游设计），桌面面板才有完整的
Key 新建、可用范围（提供商/模型白名单）等管理能力。
```

但上游 `KeysPage.tsx` 实际已经支持复制明文、启用/禁用、删除；  
所以更准确的说法是“**缺少新建和范围编辑**”，不是完全只读。

## 7. 结论

**手机面板不是“功能很少”，而是“日常使用够、管理与配置不够”。**

如果现在直接删除桌面面板，最先卡住的是：

1. 创建/管理网关 Key；
2. 给没有动态登录的 provider 加账号/改凭证；
3. 设置 GitHub Token，导致插件无法下载；
4. 修改面板密码/安全设置；
5. 完整路由和 MCP/Skill 管理。

建议按本报告 P0 → P1 → P2 的顺序补齐，再移除桌面 UI。  
在 P0 完成前，保留“桌面面板”按钮作为兜底是合理的。

## 8. 第二轮补充审计（新增遗漏）

这一轮重点检查了：

- 插件包声明的自定义 UI 页面；
- 桌面设置页里的备份、密码、安全、更新、系统信息；
- iOS 原生壳的数据持久化和文件下载能力；
- 手机独有的多服务器切换；
- supervisor 前后台生命周期对手机-only 的影响。

### 8.1 插件自定义 UI 页面没有迁移

**桌面：**

- 桌面 `app.js` 有 `adoptPluginPages`，会读取插件 `pack.json` 的 `packs[].ui[]`，把插件声明的页面挂到侧边栏和 `plugin:<pack>:<page>` 菜单。
- 这是插件生态的一部分：插件不仅能提供 provider，还能提供签到页、配置页、文档页等自定义 UI。

**手机：**

- 手机 bundle 中没有 `adoptPluginPages`；
- 手机路由表只有固定页面，没有 `plugin:` 动态路由；
- 手机插件页目前主要是安装、卸载、更新、从文件安装，不负责挂载插件声明的页面。

**影响：**

如果以后插件带自定义 UI，手机端看不到入口，必须切桌面。  
这不是当前两个插件的问题，而是插件生态的长期缺口。

**建议：**

- 手机端实现 `plugin:<pack>:<page>` 动态路由；
- 插件页面用 iframe 或安全 WebView 容器加载 `/plugins/<pack>/ui/...`；
- 插件菜单按 `packs[].ui[]` 动态注入手机“更多”页；
- 对移动端不兼容的插件页面显示明确提示。

---

### 8.2 整库备份 / 恢复 / 云同步

**桌面有：**

- 整库备份 / 恢复；
- 备份密码、恢复密钥；
- 加密备份；
- 从云端恢复；
- 云同步设置（WebDAV / S3 兼容存储）；
- 同步密码；
- 数据迁移/重置。

**手机：**

- 手机 bundle 几乎没有“整库备份/恢复/云同步”入口；
- 手机设置页只有主题、语言、API 地址、客户端识别、插件等；
- 手机没有桌面文件系统，备份文件下载/选择也需要原生支持。

**影响：**

如果只保留手机面板，用户无法在换机、重置、数据库损坏前备份账号/Key/配置。  
这是数据安全问题，属于 P0，不是体验问题。

**建议：**

- 手机设置页增加“数据”分组：备份、恢复、导出日志、重置；
- 备份生成后通过 iOS 分享面板保存到“文件”；
- 恢复使用 `UIDocumentPicker`；
- 云端同步可复用桌面 WebDAV/S3 配置；
- 至少支持加密导出/导入。

### 8.3 修改密码 / 重置管理员 / 安全设置

**桌面有：**

- 修改面板密码；
- 重置管理员账号；
- 会话失效；
- 安全设置；
- 开发者角色兼容设置；
- 认证相关开关。

**手机：**

- 手机有登录/退出，但没有“修改密码 / 重置管理员”入口；
- 手机 bundle 中“修改密码”“当前密码”计数为 0；
- 如果忘记密码，手机端无法恢复，只能清库或切桌面。

**影响：**

手机-only 时，管理员密码无法修改，也无法安全重置。

**建议：**

- 手机设置页增加“安全”分组；
- 修改密码、退出所有会话、重置管理员；
- 重置前要求二次确认，并提示会清空账号/Key。

### 8.4 iOS 原生登录态不持久

**代码事实：**

`PanelViewController` 使用：

```swift
config.websiteDataStore = .nonPersistent()
```

注释写明：

```text
代价是重启 App 后需要重新登录面板（令牌不再落在磁盘）。
```

**影响：**

- 每次杀掉/重启 App，都要重新登录面板；
- 如果以后移除桌面/PWA，只靠手机面板，这个体验会非常明显；
- 插件页、Key 页等需要登录的页面每次都要重新认证。

**建议：**

- 把面板刷新令牌存到 iOS Keychain（不是明文文件）；
- 启动时用 Keychain token 自动恢复登录；
- 或者使用 App 容器内可写的持久 WKWebsiteDataStore（需要解决 RootHide 容器路径问题）；
- 至少提供“保持登录”开关。

这是手机-only 的 P0 体验问题。

### 8.5 WKWebView 没有下载/导出处理

**现状：**

- `PanelViewController` 没有 `WKDownloadDelegate`；
- 没有 `UIDocumentPicker` / 分享面板；
- 手机端如果触发备份下载、日志导出、配置文件导出，可能没有保存位置或直接失败。

**影响：**

备份、日志、配置文件导出这些功能即使 API 有了，手机端也接不住。

**建议：**

- 实现 `WKDownloadDelegate`；
- 下载完成后用 `UIActivityViewController` 分享到“文件”；
- 恢复/导入使用 `UIDocumentPickerViewController`；
- 对 CSV/JSON/ZIP 文件提供明确的保存/分享流程。

### 8.6 客户端配置导出 / 写入桌面客户端

**桌面有：**

- 把网关 Key/Base URL 写入 Claude Code、Codex、Cursor 等本机客户端配置；
- 写入前展示差异、自动备份；
- 多客户端安装目标。

**手机：**

- 手机无法访问桌面客户端的文件系统；

- 手机 bundle 中没有对应的安装目标管理。

**影响：**

这个功能本身是桌面场景，手机-only 不一定需要“写入”，但至少需要：

- 复制 Base URL；
- 复制 Key；
- 生成 OpenAI/Anthropic 兼容配置文本；
- 分享配置片段。

**建议：**

把它定义为“复制/分享配置”，而不是“安装到客户端”。

### 8.9 多服务器（手机独有）需要逐服务器配置

### 8.10 Supervisor 生命周期对手机-only 的影响

当前 supervisor 方案：

```text
App 前台 → 网关启动
App 后台 → 网关停止
App 被杀 → 15 秒后停止
```

这对“手机面板 UI”本身没问题，但需要明确：

- App 后台时，外部 API 客户端无法访问网关；
- 后台签到、定时任务、长连接会中断；
- 手机-only 用户如果希望锁屏后仍提供 API，必须改回 A1 常驻模式；
- 面板内的长任务（插件下载、备份）在 App 后台可能被中断。

这不是 UI 缺口，但属于产品行为，需要在手机-only 版本里明确提示。

### 8.15 不应硬搬到手机的桌面能力（硬限制）

以下不是“UI 没适配”，而是 iOS 环境限制，产品上应明确标注或提供替代方案：

- **本地 stdio MCP / Skill 进程**：手机 App 不能像桌面一样启动任意本地命令行 MCP；只能接远程 HTTP MCP，或由网关侧托管。
- **写入桌面客户端配置**：手机不能访问 Claude Code、Codex、Cursor 等桌面客户端文件；只能复制/分享配置文本。
- **桌面安装包/自动更新**：Windows/macOS/Linux 安装器和托盘/自启动/快捷键不适用于 iOS；手机更新走 Sileo/deb。
- **后台常驻 API**：supervisor 方案会在 App 后台停网关；如果产品需要锁屏持续 API，必须回到 A1 常驻模式，不能靠手机 UI 解决。
- **桌面文件系统相关功能**：日志导出、备份文件、插件本地文件安装需要 iOS 原生下载/分享/文件选择器支持，不能直接复用浏览器下载。

这些能力如果保留桌面入口，建议在手机端明确提示“桌面专属”，不要留一个点击后失败的按钮。

| 自定义提供商 | 未见完整 CRUD | 新建/编辑/拉模型/删除 | **P1** |
| 插件 | 安装/更新/启停/卸载、更新通道、自动更新、GitHub 镜像 | GitHub Token、插件自定义 UI 通用挂载 | **P0 token / P1 UI** |
| 安全 | 登录/退出 | 修改密码、重置管理员、会话失效、安全设置 | **P0** |
| 备份 | 无 | 整库加密备份/恢复、云同步 | **P0** |
| 日志/请求 | 列表、筛选、详情、暂停 | 重放、导出、列设置、完整快照 | **P2** |
| 账号表格 | 卡片/筛选/排序 | 列设置、批量、拖拽分组 | **P2** |
| 系统信息 | `SystemInfoSheet` 已有版本/运行形态/数据目录/日志/端口/统计 | 服务控制、安装信息更完整 | **P2** |
| 多服务器 | 有 `servers` 切换 | 无 | 手机独有 |
| PWA/安装 | 有 PWA 安装、AppUpdatePanel | 桌面安装器/自更新 | 平台差异 |
| 后台 API | supervisor 前台启停 | 桌面可常驻 | 产品差异 |

结论：

- 手机端不是“缺所有管理”，而是“缺**写操作/编辑器/数据安全**”；
- P0 仍然是：Key 新建/范围、账号凭证、GitHub Token、安全、备份、登录持久化；
- MCP/Skill 不是完全缺失：Agent 页有网关侧管理，缺的是本机安装；
- 系统信息不是缺失：已有 `SystemInfoSheet`，缺服务控制。

## 9. 更新后的 P0 清单

结合第二轮审计，移除桌面前至少需要：

1. **手机 Key 管理**（新建/编辑/删除/范围）
2. **账号凭证编辑 + 导入/导出**
3. **GitHub Token**
4. **插件设置/更新策略/签名策略**
5. **修改密码/重置管理员/安全设置**
6. **整库备份/恢复**
7. **iOS 面板登录持久化（Keychain）**

外加：

8. **文件下载/分享/恢复的原生桥接**
9. **插件自定义 UI 页面**
10. **完整路由 / MCP / Skill / 自定义提供商**

其中 1–7 是“手机-only 能否安全日常使用”的底线；  
8–10 是“能否替代桌面面板全部管理能力”的完整度。

## 10. 最终建议

- 短期：保留桌面面板按钮，作为 P0 未完成前的兜底。
- 中期：先做 P0（Key、账号凭证、GitHub Token、安全、备份、登录持久化），再做插件自定义页面。
- 长期：补齐路由、MCP/Skill、自定义提供商、批量/表格能力后，再移除桌面 UI 和原生“桌面面板”按钮。
- 如果产品决定某些桌面能力（写客户端配置、桌面安装包、MCP 文件安装）永远不做手机版，应在手机端明确标注“桌面专属”，而不是留一个会失败的入口。
