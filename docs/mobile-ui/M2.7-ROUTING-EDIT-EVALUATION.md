# M2.7 路由组「结构性编辑」语义评估（先评估，后改代码）

> 日期：2026-11-09 · 评估先行，**本文件写完之后**才动代码。
> 依据：上游 v3.4.2 `api/routing_groups.rs`、`config/routing_groups.rs`、`http.rs` 路由表，
> 以及本项目 ② 那轮已落地的 `pages/routing-group-edit-sheet.tsx`。

## 0. 结论（一句话）

**可以安全实现，但必须带三条护栏**：① 原样 round-trip 组对象；② 保存前用**无副作用的预览**
接口看候选队列；③ 改「对外模型 ID」时明确告知两件事（会清该模型的会话粘性、客户端要用新名字）。
否则「结构性编辑」会在用户不知情的情况下改变线上路由行为。

## 1. 契约（已核到源码）

路由：
```
GET  /api/routing/groups   → get_groups
PUT  /api/routing/groups   → put_group      ← 保存/删除都走它
POST /api/routing/preview  → preview        ← 无副作用草稿预演
```

`PUT /api/routing/groups` 载荷（`deny_unknown_fields`，camelCase）：

```jsonc
{ "id": "<组 id>", "group": { …RoutingGroup… } | null, "revision": "<sha256>" }
```

- `group: null` = **删除这个组**
- `revision` = 整组内容的 SHA-256（`config::routing_groups::revision`），保存时回传**打开时读到的**那个
- 不一致 → **409**「路由配置已在其他位置修改…」
- 组结构：

```rust
RoutingGroup  { id, name, model, description="", strategy, sticky, members[] }   // deny_unknown_fields
RoutingMember { id, provider, model, included, accounts: Vec<String> }          // deny_unknown_fields
```

服务端校验（文案原文，界面直接显示它）：

| 规则 | 文案 |
|---|---|
| 组/成员标识：非空、≤128、仅 `[A-Za-z0-9-_.]` | 路由组或成员标识无效 |
| 组名非空、≤64 字符、无控制字符；说明 ≤500 字符 | 组名不能为空或超过 64 个字符，说明不能超过 500 个字符 |
| `model` 非空、去空格后不变、归一化后等于自身（小写） | 对外模型 ID 不能为空，请去掉首尾空格并使用小写英文字母 |
| `MAX_GROUPS = 500`、`MAX_MEMBERS = 256` | 一个路由组最多允许 256 个成员 |
| 成员 id 唯一、(provider, model) 不重复 | 同一提供商的同一模型不能重复加入，成员标识也不能重复 |
| 成员的 provider/model 有效 | 成员的提供商或模型 ID 无效 |
| 成员 `accounts` 非空、不重复、格式正确 | 成员的参与账号为空、重复或格式不正确 |
| 成员账号必须存在于**当前可见账号**（`validate_members(group, old, &accounts)`） | （见 `routing_groups::validate_members`） |

## 2. 字段级影响（改它到底改变了什么）

| 字段 | 影响 | 风险 |
|---|---|---|
| `id` | 组的身份，**不可改**（改 id = 建新组） | — （界面里只读） |
| `name` / `description` | 纯展示 | 无 |
| **`model`** | **对外模型 ID**：客户端按这个名字请求，决定**请求匹配面**；也决定会话粘性的键 | ⚠️ **高**：改了等于换入口名，客户端要跟着改；**保存后会清空该模型的粘性会话** |
| `strategy` | 组内选号策略（`RouteStrategy::from_id`） | 中：改完选号顺序立刻不同 |
| `sticky` | 会话粘性模式（`StickyMode::from_id`） | 中：决定了粘性 TTL 与是否粘住 |
| `members[].included` | 成员是否参与（② 已可改） | 低 |
| `members[].accounts` | 该成员的**参与账号白名单**（空 = 不限制） | 中：缩小范围会立刻把账号移出队列 |
| `members[]` 增删 | 组的成员集合 | 中：`provider`+`model` 唯一 |
| `members[].provider/model` | 成员的来源与上游模型 | 中：provider 必须与账号一致 |

## 3. 两条「会改变运行态」的行为（必须让人知道）

1. **保存后清掉旧 `model` 的粘性会话** —— `put_group` 里写死的：

   ```rust
   if let Some(old) = old { state.upstream().clear_route_sticky(None, Some(&old.model)); }
   ```

   这是**有意**的：组的成员变了，粘在旧成员上的会话不该继续沿用。但它意味着
   「我只是改了个策略」也会让正在进行的会话重新选号 —— 界面要说清。
2. **改 `model` 会换入口名**：对外模型 ID 变了，客户端请求里的 `model` 必须跟着改，
   否则会落到别的路由或直接不匹配。

## 4. 三条护栏（实现时必须带）

1. **原样 round-trip**：`RoutingGroup` 是 `deny_unknown_fields`，所以提交的对象
   **不能多一个键也不能少一个键**。做法：读到的组整份留存，编辑时只覆盖用户动过的字段
   （展开写法），提交原样回传。② 那轮已经是这个做法，继续沿用。
2. **保存前预览**：`POST /api/routing/preview` 是**无副作用**的草稿预演，返回候选队列、
   `member_blocked`（冷却/不可用）、以及 `queue`。结构性编辑最需要的正是它 ——
   改完先看「现在会选中哪些账号、谁被挡了」，再决定保存。
3. **改 `model` 的显式确认**：文案要说清两句（会清粘性 / 客户端要用新名字），
   不放进"保存成功"的提示里轻描淡写。

## 5. 与已有实现的关系

② 那轮已经：用 `PUT /api/routing/groups` + `revision`（同一接口）、支持 组名/说明/成员参与开关、
并且已经在重读时按 revision 处理并发。**这次是给同一份载荷加字段**：

| 字段 | ② 现状 | 本次 |
|---|---|---|
| `name` / `description` | ✅ 可改 | — |
| `members[].included` | ✅ 可改 | — |
| **`model`** | ❌ 只读 | ➕ 可改（带确认） |
| **`strategy` / `sticky`** | ❌ 只读 | ➕ 可改 |
| **`members` 增删 / `members[].accounts`** | ❌ 只读 | ➕ 可改（账号范围用当前账号列表） |
| 删除整组 | ❌ | ➕（`group: null`） |
| 保存前预览 | ❌ | ➕（`POST /api/routing/preview`） |
